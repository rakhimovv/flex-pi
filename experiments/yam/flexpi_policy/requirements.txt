# YAM FlexPi deployment-only requirements.
#
# Use this to set up a venv that can run:
#   - experiments.yam.flexpi_policy.smoke_test
#   - experiments.yam.flexpi_policy.yam_bridge
#   - experiments.yam.flexpi_policy.yam_raiden_bridge (raiden side; see notes below)
#
# Install order (from the FlexPi project root):
#
#   python -m venv .venv-deploy
#   source .venv-deploy/bin/activate
#   pip install -e .                                          # the flexpi package
#   pip install -r experiments/yam/flexpi_policy/requirements.txt
#
# The `pip install -e .` step pulls in every model-side dep declared in
# FlexPi/pyproject.toml (torch + cuda 12.8, transformers, accelerate,
# safetensors, hydra-core, omegaconf, pyarrow, av, einops, timm, …).
# This file adds ONLY the small extras our deploy code uses on top of that.
#
# System binaries (must be on PATH for the smoke test's recorded mode):
#   ffmpeg          # depth MKV → raw bytes  (flexpi.datasets.lerobot.utils.depth_codec)
#   ffprobe         # depth MKV stream introspection
#
# raiden integration:
#   - YamFlexPiRaidenBridge is meant to be run from the raiden venv
#     (typically /home/<user>/projects/YAM_robot/.venv), not this one.
#   - That venv must have `raiden` importable (pip install -e raiden/).
#   - In that venv, add `PYTHONPATH=/path/to/FlexPi:$PYTHONPATH` so it can
#     import `experiments.yam.flexpi_policy.*` and `flexpi.*`. Most users
#     install flexpi editable into the raiden venv directly to avoid
#     PYTHONPATH juggling.

# --- Deploy-only extras (not in flexpi/pyproject.toml) ---
# opencv-python: used by YamFlexPiRaidenBridge._dump_first_obs to write
# RGB / depth PNGs to ~/yam_flexpi_obs_debug/ on the first step. Soft-fails
# in the bridge if missing (dump just skipped), but recommended for the
# first deploy session so you can visually verify camera streams.
opencv-python>=4.8
